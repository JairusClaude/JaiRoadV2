# JaiROADS Android field workspace

Install JaiROADS Review alongside earlier APKs. It uses the review service and its normal accounts. The build has a separate data directory so earlier apps and their drafts stay on the phone.

Online sign-in downloads recent authorized work in the background and opens the normal dashboard. The app keeps the hosted page open and shows the bundled workspace when the link or server is unavailable. The cached workspace uses the same role theme and module names. Sign in with the same credentials on the same phone in airplane mode to reopen it after closing the app. Engineers can save and edit roads, projects, records, and monthly text reports locally, with manual coordinates when maps are unavailable. The app automatically tries to sync at reconnect, resume, and intervals while open. Retry uses the original operation ID until Laravel confirms the database transaction. Review unresolved conflicts before retrying. Viewer access is read-only.

Supported files can be attached locally to the workspace. Upload them through the online private Storage workflow. Cached road alignments over 32 KiB are retained on the server and must be edited in the online map. Admin and SuperAdmin use the online dashboard.

The review service enables field routes with `JAIROADS_ANDROID_FIELD_ENABLED=true` and uses the private schema in `database/proposals/android_field_receipts.sql`. The APK includes neither database credentials nor Supabase API keys.

The authentication page now enters as a full-screen vertical transition. Swipe down from non-interactive content (the branded header always works when at the top) or press Android Back to return to the same preview slide. On short screens, the form remains scrollable; the Explore button is removed. The normal hosted dashboard remains primary after successful online authentication; a failed background cache refresh must not force an otherwise healthy dashboard into the local workspace. The bundled workspace uses role and appearance tokens and a fixed bottom connectivity/status banner. It remains a limited offline equivalent, not a full cache of every hosted page. Keep earlier APKs installed until all locally saved records are synchronized; this review app has a separate application ID.

## Remaining offline-first release requirement

The current fallback is a separate bundled HTML workspace with a limited data snapshot. Do not mark it as full online/offline parity or make further cosmetic copies of hosted pages. The target is to use the actual existing React/Inertia dashboard, layout, navigation, operations, detail pages and forms in both connectivity states, with offline-capable data and mutation adapters. Reuse the encrypted, account-scoped local vault and idempotent receipt queue. Cache only authorized page data and explicitly supported private file content, with appropriate limits, expiry and lock behavior. Offline saving needs to persist validated edits and their dependencies before displaying a success message, including a safe queued upload path for attachments. Synchronization must revalidate permissions, handle version conflicts, retry without duplicates, and never delete unacknowledged local work. Features that need network resources must have explicit local fallbacks, not fabricated data or raw server errors.

Acceptance requires the same real dashboard and routes before and after disconnecting, project/record/detail/file navigation without network where data was prepared, local create/edit/save and file persistence across app restarts, automatic authenticated synchronization, and verified receipts/database and private Storage results on reconnect. The present build does not meet that release requirement; its existing fallback and queue remain intact.

### v0.4.3 offline capability increment

Adds an interactive local Leaflet road-line map with the existing approximate provincial outline (no network basemap tiles), cached project/record/report details, bounded encrypted caching of authorized documents and photos, native user-directed file export, and queued document/photo upload through the existing private-storage handlers and transactional receipts. Photos require a monthly update; documents require a maintenance record. Earlier local attachments without an explicit upload target remain retained for review. The server must be deployed with the new Android field attachment endpoint and existing receipt table. The field cache is bounded (4 MiB per file, 8 MiB encoded automatic/download cache budget); unavailable/oversized files are not represented as downloaded. This is not yet the same shared React/Inertia UI or a complete offline street basemap. Physical-device, backend, private Storage, and reconnect tests are still required.

### v0.5.0 shared workspace review

The Android package now contains the actual canonical React/Inertia frontend build. An unlocked Engineer or Viewer with a prepared dashboard can use those same pages in a single mounted workspace while connectivity changes. Online visits use the existing server. Offline visits use account-scoped encrypted snapshot projections and local mutations use the existing receipt queue. Cached documents and photos use the existing private-file adapter. The fallback from older unprepared vaults remains available for recovery, not as the normal offline interface. Offline page data is bounded and may be older than the server; network-only management, deletion, settings and uncached data require connectivity. No full offline street-tile download is included. Verify Android build and device/backend acceptance before release.
