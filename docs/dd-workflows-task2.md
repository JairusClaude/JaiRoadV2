Lifecycle actions re-resolve the authenticated actor within serialized transactions. Retirement coordinates with existing provisioning and uses login → canonical account → Engineer lock ordering, compatible with password updates. Account changes retain every credential byte. Reassignment uses project → record locks and the existing eligibility service's shared locks. Current transactional AuditLog insertion failure aborts each business transaction; exceptions are not swallowed. Retries do not persist intermediate events.

The current AuditLog architecture is deliberately retained, including its existing notification behavior. New operations use existing `UPDATE` vocabulary and safe explicit old/new field snapshots. Reassignment snapshots contain old/new manager IDs and names. No passwords, hashes, Fortify secrets, tokens, private paths or file bytes enter these new payloads. Profile, account and assignment changes are distinct business mutations during retirement. This task does not claim to replace the current notification fan-out, resolve LOGIN auditing or install database append-only enforcement.
