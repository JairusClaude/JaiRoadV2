## npm update and compatibility exception

Before: **7 moderate affected package entries, 0 high, 0 critical**. They represent minimatch's advisory and its TypeScript-ESLint dependency chain, not seven independent production exploits.

- Transitive development minimatch **10.2.6 → 11.0.4** under `@typescript-eslint/typescript-estree` only.
- New required development transitive `@isaacs/nonrecursive-glob-match` **1.0.3**.
- Existing root minimatch 3.1.5 and other packages stay locked; runtime frontend package versions do not change.
- The latest inspected TypeScript-ESLint parser still requests `^10.2.2`, while the advisory's fixed series begins at 11.0.1. A parent-scoped npm override pins patched 11.0.4 rather than ignoring the advisory or indiscriminately upgrading ESLint/TypeScript.
- The actual caller invokes `minimatch(filePath, pattern, { dot: true })`; it does not expose user-submitted glob optimization through a business endpoint. Six real positive/negative/dot-path comparisons matched old/new behavior. Repository ESLint, TypeScript and build checks validate integration.
- minimatch 11 supports Node20 or >=22; project CI uses Node22 and local verification uses Node24.22.1. Node18 is no longer supported by this overridden dev dependency; it is not the configured CI platform.
- Remove/revisit the override once the upstream parser accepts a patched release naturally. Do not replace it with an audit ignore.

The override was applied through npm's supported package-lock generation; `npm ci` succeeded, followed by a valid `npm ls` tree and `npm audit --audit-level=high`: **zero vulnerabilities at every severity**.

Primary advisory: https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249 (CVE-2026-118764). It describes pattern amplification and fixes from 11.0.1. No production user-controlled glob path was demonstrated here.
